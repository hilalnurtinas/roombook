## Files to change or add

- `app/models/__init__.py` — package init, re-exports `Base`
- `app/models/base.py` — SQLAlchemy 2.x `DeclarativeBase` (`Base`), shared by all models
- `app/models/user.py` — `User` model: `id` (PK, int), `name` (str). Minimal — no auth fields.
- `app/models/room.py` — `Room` model: `id` (PK, int), `name` (str), `capacity` (int), `owner_id` (FK → `users.id`)
- `app/models/booking.py` — `Booking` model: `id` (PK, int), `room_id` (FK → `rooms.id`), `user_id` (FK → `users.id`), `start_at` (timestamptz), `end_at` (timestamptz), `status` (str: `pending`/`confirmed`/`rejected`/`cancelled`/`skipped_conflict`), `created_at` (timestamptz, server default now)
- `app/schemas/__init__.py`
- `app/schemas/booking.py` — Pydantic v2 schemas: `BookingCreate` (`room_id`, `start_at`, `end_at`, with a `model_validator` enforcing `end_at > start_at` — AC-9), `BookingRead` (echoes room/start/end/status — AC-1), `ConflictingBooking` (start/end of a conflicting existing booking — AC-5), `SuggestedSlot` (start/end — AC-6/7)
- `app/errors.py` — add typed exceptions: `RoomNotFoundError` (404, AC-8), `BookingConflictError` (409, carries `conflicts: list[ConflictingBooking]` and `suggestions: list[SuggestedSlot]` — AC-5/6/7), `UnresolvedUserError` (401, AC-11)
- `app/auth.py` — `get_current_user` FastAPI dependency: reads `X-User-Id` header, loads the `User` row; missing header or no matching row → raises `UnresolvedUserError` (AC-11). Isolated in its own module since it's a stand-in for real auth (spec's Constraint #1) and must be trivially replaceable later.
- `app/services/booking.py` — `create_booking(session, current_user, payload) -> Booking`:
  - loads the `Room`, raises `RoomNotFoundError` if missing (AC-8)
  - queries existing bookings on that room with `status NOT IN ('cancelled', 'rejected')` overlapping `[start_at, end_at)` (AC-2/3/4/12/13)
  - on conflict: computes up to 3 suggested slots (see below) and raises `BookingConflictError(conflicts, suggestions)`
  - on success: inserts a `Booking` row with `status='pending'` (AC-1/AC-2 domain rule BR-2), relies on the DB exclusion constraint as the final backstop (AC-14)
- `app/services/slots.py` — `find_free_slots(existing_bookings, room_id, requested_start, duration, window=timedelta(hours=24), limit=3) -> list[SuggestedSlot]`: walks the 24h window forward from `requested_start`, skipping over each existing (non-cancelled/rejected) booking's span, collecting up to `limit` gaps of at least `duration` (AC-6/7) — pure function, no DB access, so it's unit-testable without a database.
- `app/routers/booking.py` — `POST /bookings`, depends on `get_session` and `get_current_user`, calls `services.booking.create_booking`, returns `BookingRead` (201) on success; typed exceptions bubble to the existing global exception handlers in `app/main.py`
- `app/main.py` — register `booking_router`; add exception handlers for `RoomNotFoundError`, `BookingConflictError` (409, includes `conflicts`/`suggestions` in the body), `UnresolvedUserError` (401) — following the existing `AppError` handler pattern
- `alembic/versions/0002_bookings_schema.py` — creates `users`, `rooms`, `bookings` tables; enables `btree_gist` extension; adds a Postgres `EXCLUDE` constraint on `bookings` — `EXCLUDE USING gist (room_id WITH =, tstzrange(start_at, end_at, '[)') WITH &&) WHERE (status NOT IN ('cancelled','rejected'))` — this is the DB-level backstop required by `docs/domain.md`'s invariant and the mechanism that makes AC-14 provable
- `tests/conftest.py` — add a second fixture, `two_real_sessions`, that opens **two independent connections** directly against `TEST_DATABASE_URL` (not the single rolled-back-transaction `test_session` fixture, which can't model two concurrent transactions) for the concurrency test; explicit teardown deletes any rows it inserted, since it can't rely on the rollback trick
- `tests/models/__init__.py`, `tests/models/factories.py` — tiny helpers to insert a `User`/`Room`/`Booking` row directly for test setup (no create-room/register-user endpoints per spec's Constraints)
- `tests/services/test_slots.py` — unit tests for `find_free_slots` (pure function): empty existing list, single blocking booking, back-to-back boundaries, no gap in window, multiple gaps capped at 3
- `tests/services/test_booking_conflict.py` — integration tests (real DB session) for AC-1, 2, 3, 4, 8, 12, 13 at the service layer
- `tests/services/test_booking_concurrency.py` — AC-14, using `two_real_sessions`
- `tests/routers/test_booking.py` — HTTP-level tests for AC-1, 5, 6, 7, 9, 10, 11 (request/response shape, status codes, body content)
- `README.md` — short note that `POST /bookings` exists and requires `X-User-Id` (append, don't rewrite)

## Risks & open questions

- **The transactional-rollback test fixture (`test_session`) can't prove real concurrency.** Every
  existing test wraps its work in one connection's transaction, rolled back at the end — two
  "concurrent" calls sharing that connection would just serialize on the same transaction, proving
  nothing about AC-14. Recommendation: add the separate `two_real_sessions` fixture (two real
  connections, real commits, explicit `DELETE` teardown) rather than trying to force AC-14 through
  the existing fixture. This is the only test file that doesn't get transaction-rollback isolation
  for free — flagging so it isn't mistaken for sloppiness later.
- **Enforcing BR-1 at the DB layer requires a Postgres `EXCLUDE` constraint + `btree_gist`
  extension**, which is more exotic than a plain unique constraint and needs superuser/extension
  privileges on the test/dev DB. Recommendation: enable the extension in the migration itself
  (`CREATE EXTENSION IF NOT EXISTS btree_gist`); if the DB user lacks privilege in some environment,
  that's a deployment/infra concern, not a reason to drop the constraint — domain.md explicitly
  requires a DB-level backstop, not just a service-layer check (which alone cannot prevent a true
  race).
- **`status` is stored as a plain string, not a Postgres enum type**, to keep the `EXCLUDE`
  constraint's `WHERE (status NOT IN (...))` simple and to avoid an enum-alteration migration
  headache later (a new status value would need an `ALTER TYPE`). Recommendation: accept this
  trade-off for v1; a `CHECK (status IN (...))` constraint still guards against garbage values.
  Flagging since `docs/conventions.md` doesn't state a preference either way.
- **Overlap semantics for the exclusion constraint use a half-open range `[)`** (start inclusive,
  end exclusive) so that back-to-back bookings (AC-4) don't collide — this must exactly match the
  service-layer query's overlap condition (`start_at < requested_end AND end_at > requested_start`)
  or the DB constraint and the app-level conflict message will disagree on edge cases.
  Recommendation: share one Python constant/comment cross-referencing the two, and cover the exact
  boundary in `test_booking_conflict.py` (AC-4) so a drift between them fails a test, not silently.
- **`find_free_slots` walking a 24h window could, in the worst case (many tiny bookings), do a lot
  of small comparisons.** Recommendation: not a real risk at v1 scale (a room's bookings in any
  24h window is a small list); no pagination/optimization needed now — noting only so it isn't
  silently over-engineered.
- **`X-User-Id` stand-in accepts any integer a client sends with no proof of identity** — this is
  intentional per the spec's Constraints (real auth is a separate spec) but is a real, temporary
  security gap. Recommendation: document this loudly in `app/auth.py`'s module docstring-equivalent
  (a one-line comment) and in the README note, so it's never mistaken for a finished auth story
  during review.
