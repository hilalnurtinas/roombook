## Risks & open questions
- **Alembic autogenerate needs at least one model to target, but this spec adds no domain models.**
  Recommendation: create migrations with an empty `upgrade()`/`downgrade()` (or a trivial marker
  table) by hand rather than via `alembic revision --autogenerate`, since there's nothing to
  diff yet. The first real feature spec will add the first autogenerated migration against actual
  models.
- **`GET /health` DB check could mask connection-pool issues if it only checks "engine exists."**
  Recommendation: implement it as `SELECT 1` through a real session, so a broken `DATABASE_URL` or
  down DB genuinely fails the endpoint (needed for AC-1 to mean something).
- **Docker vs. local dev-loop speed.** Recommendation: keep `docker-compose.yml` for the
  "single command" and CI-equivalent path (AC-1), but don't require Docker for the fast
  edit/test loop — `DATABASE_URL`/`TEST_DATABASE_URL` in `.env.example` can point at a locally
  running Postgres too. Not a blocker, just noting both paths exist.
- **mypy strictness level** — `docs/conventions.md` says "strict-ish," which is vague enough to
  cause drift later. Recommendation: set `strict = true` in `pyproject.toml`'s `[tool.mypy]` now,
  on an otherwise-empty codebase, so strictness is a starting floor rather than a later fight.
  Flagging because this slightly firms up conventions.md's wording — no doc edit needed unless
  you want it made explicit there too.
